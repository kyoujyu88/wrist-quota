### M1 の実装（Claude Code）

- 依頼者から「確認を減らして進めてほしい」と一任を受け、SPEC.md 11 章の未決事項のうち実装言語（Go）・製品名（`wrist-quota`）・複数 PC の扱い・リセット通知の対象を推奨案で確定した。ライセンスは未決のまま。
- Go 1.27.1 を `~/.local/go` に導入した（公式配布物、SHA-256 を照合）。
- 収集（Claude Code・Codex）、ルール評価、ntfy 送信、設定の保存、ローカル Web UI、ステータスライン登録を実装した。外部ライブラリは使っていない。
- リセット通知の sequence ID は「プロバイダ・窓・その周期のリセット時刻」から作る。周期ごとに ID を変えるのは、次の周期の通知が前の通知の「更新」として扱われて鳴らない恐れを避けるため。
- リセット時刻は観測ごとに数秒ずれることがあるため、10 分以内の差は同じ周期として扱う。予約の入れ直しは 1 分を超えてずれた時だけ行う。
- 送信の失敗は次の収集周期で再試行し、5 回で諦める。1 日の送信数は 200 通で止める（ntfy.sh の上限は 250 通）。
- 実プロセスをテスト用の ntfy サーバー相手に動かし、受け入れ条件 1・2・4・7・8・9 を確認した。3・5・6 は実機の受信確認が残っている。

### 方針の決定と仕様書 v0.1 の作成（claude.ai チャット）

- 表示は通知方式にする。Wear OS と watchOS の両方に 1 つの実装で届き、ウォッチ用ネイティブアプリが不要なため。
- 通知経路は ntfy。Android と iOS の両方にアプリがあり、送信は HTTP POST だけで済むため。
- 集計役は利用者の PC の常駐アプリにする。一般の利用者はサーバーを持たず、スマホ単体ではローカルログが読めないため。
- データは各ツールが PC 上に公式に書き出す情報だけを使う（AI の提案。ユーザーの明示的な承認は未取得）。
- 設定画面はブラウザで開くローカル Web UI（127.0.0.1）。
- 実装言語は Go の単一実行ファイルを推奨（AI の提案。未確定）。
